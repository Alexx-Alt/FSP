## 2. Главная идея, которую нужно защищать

ИТ-MATCH PRO не отвечает на вопрос «кто лучший программист вообще». Он отвечает на вопрос:

> **кто подходит под конкретную потребность работодателя, почему подходит, какие доказательства уже есть, чего не хватает и какой следующий шаг нужно сделать.**

Цепочка:

`профиль → категория → заявленный грейд → assessment → evidence → explainable match → взаимный шаг → Process Center → аналитика`

Неподвижные правила:

1. Кандидат сам выбирает желаемый грейд.
2. Подтверждённый грейд изменяет только assessment.
3. FSP ID не назначает грейд; он добавляет evidence и влияет на ранжирование внутри сопоставимой категории.
4. Неподтверждённый грейд не скрывает кандидата автоматически.
5. Контакты кандидата закрыты до взаимного шага.
6. Критический Match Engine детерминирован и работает без GPU/LLM.

## 3. Демонстрация на 7–10 минут

### Шаг A — кандидат (2–3 минуты)

1. Войти `candidate@fsp.demo`.
2. Показать профессиональный паспорт и желаемый/подтверждённый грейд.
3. Открыть knowledge graph: `Граф / Дерево`, evidence states, поиск, `Gaps`.
4. Запустить live assessment:
   - вопросы по одному;
   - fullscreen;
   - смена вкладки/blur/copy/paste фиксируются как сигналы;
   - практическая code-задача;
   - спорная попытка уходит на review, а не банится автоматически.
5. Вернуться к Match и открыть «Почему» по вакансии.
6. Сравнить 2–3 компании.
7. Нажать «Откликнуться», оставить сообщение.

### Шаг B — работодатель (2–3 минуты)

1. Войти `employer@fsp.demo`.
2. Открыть `/employer/jobs`.
3. Показать, что потребность задаётся через категорию, грейд, стек, зарплату, город и формат.
4. Вернуться в `/workspace` и показать shortlist.
5. Открыть разбор кандидата: совпадения + gaps.
6. Сравнить несколько кандидатов.
7. Отправить адресное приглашение с сообщением.
8. Показать Process Center: ЛПР, задачи, комментарии, следующий шаг, история.

### Шаг C — администратор / качество (2 минуты)

1. Войти `admin@fsp.demo`.
2. Открыть `/jury-demo`.
3. Показать точные веса критериев ФСП.
4. Показать test-retest, integrity, pipeline, города и компании.
5. Перейти в архитектуру и подчеркнуть no-GPU путь.

## 4. Почему Match объяснимый

Итоговый score не является единственным основанием. Для каждой пары `кандидат ↔ вакансия` отдельно считаются:

- совпадение категории;
- fit подтверждённого грейда;
- покрытие обязательного стека;
- пересечение зарплатного ожидания и предложения;
- совместимость формата работы;
- небольшой verified FSP evidence boost;
- список совпавших навыков;
- список gaps;
- человекочитаемые reasons.

Маршруты:

- `invite` — высокое соответствие;
- `clarify` — нужно уточнить;
- `perspective` — перспектива;
- `observe` — наблюдать.

У кандидата `invite` визуально означает «высокое соответствие / откликнуться», а действие «Пригласить» доступно работодателю.

## 5. Почему тест устойчивее обычного фиксированного теста

- банк заданий;
- выбор вопросов по категории и сложности;
- случайный порядок/вариант;
- одна задача на экран;
- практическое решение;
- фиксация fullscreen/visibility/focus/copy/paste/context menu/rapid insert;
- code similarity как сигнал, а не автоматический приговор;
- integrity score отдельно от предметного score;
- reviewRequired при повышенном риске;
- test-retest через `retest_of`;
- cooldown смены/повторной проверки грейда.

Важно: **один integrity-сигнал не равен доказанному списыванию**.

## 6. Privacy / 152-ФЗ слой

После `06_mega_update_compliance.sql` кандидат управляет:

- участием профиля в новых подборках работодателей;
- согласием на обработку данных;
- согласием на публикацию профессионального профиля;
- mock-связью с FSP ID.

Match Engine исключает из новых подборок кандидатов, которые отключили публикацию. Контакты остаются закрыты до взаимного шага независимо от этих настроек.

## 9. Техническая воспроизводимость

### Обычный локальный запуск

```bash
composer install
npm install
php artisan key:generate
php artisan optimize:clear
php artisan serve
npm run dev
```

### Docker

```bash
docker compose up --build
```

При первом создании MySQL volume SQL-файлы `00..06` из `database/fsp_match_v6` применяются автоматически по имени.

Сброс demo-БД в Docker:

```bash
docker compose down -v
docker compose up --build
```
