# FSP / ИТ-MATCH PRO — план переноса функционала из прототипов

Источники для развития ветки `feature/fsp-match-v6-analytics`: визуальный язык `fsp-match-nova-final-v5`, продуктовые и технические механики `fsp-match-3.0-clean`, ответы постановщиков и текущая Laravel/Vue/MySQL реализация.

## Phase 1 — Candidate Center

Статус: реализуется в текущей ветке.

- крупный отдельный кабинет кандидата;
- профессиональный паспорт;
- Career Compass;
- направления Backend / Frontend / Data / ML/AI / DevOps / Full-stack;
- рабочий assessment с банком вопросов в MySQL;
- test-retest история и cooldown смены грейда;
- integrity-сигналы без автоматического обвинения кандидата;
- Evidence Tree;
- Explainable Match;
- FSP ID evidence;
- Process Center кандидата;
- общий scale-pass для старого workspace.

## Phase 2 — Employer Center

- CRUD вакансий и hiring brief;
- фильтры и сохранённые поиски;
- подбор по вакансии и объяснение match;
- сравнение кандидатов side-by-side;
- shortlist;
- адресное приглашение;
- gap task и регулярные задачи работодателя;
- несколько ЛПР и ответственность за следующий шаг;
- карточка компании и benchmark с другими компаниями;
- talent pool / перспективные кандидаты.

## Phase 3 — Admin / Quality Lab

- редактор банка assessment;
- версии и уникальность вариантов;
- статистика вопросов и test-retest;
- integrity review;
- очередь модерации;
- Validation Lab на синтетических парах «вакансия-кандидат»;
- аудит match-решений;
- управление FSP ID demo-интеграцией;
- обзор кандидатов, компаний, городов и процессов целиком.

## Phase 4 — Shared mechanics

- внутренний чат после принятия приглашения;
- самостоятельные отклики как дополнительный канал;
- swipe / mutual interest как быстрый режим поиска;
- внешние evidence: проект, сертификат, портфолио, рекомендация;
- центр уведомлений;
- trust / quality-сигналы компании;
- skeleton ATS/API интеграции и документация OpenAPI.

## Неподвижные правила

- желаемый грейд выбирает кандидат;
- официальный грейд определяет только assessment;
- FSP ID не назначает грейд, а усиливает evidence и ранжирование;
- неподтверждённый грейд не скрывает человека;
- контакты открываются после принятия адресного приглашения;
- основной путь не требует GPU;
- механика должна быть объяснимой и воспроизводимой.
